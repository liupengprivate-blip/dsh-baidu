# dsh-baidu 需求说明（澄清版 v1）

> 本文只把最初的一句话需求写清楚，**没有新增功能点**。目标是消除实现歧义，
> 让「搜索引擎模拟器」这一版保持 demo 级别：一个入口、一个输入框、一次搜索、
> 一列结果。

## 1. 一句话目标

在 DeepSeek Harness 的 Web 界面左侧栏增加一个入口，点开是一个**模拟的搜索引擎
页面**；用户输入关键词并点击搜索后，页面调用 **DSH 本地搜索接口**，列出**前 10 条**
搜索结果。

## 2. 本期做 / 本期不做

| 本期做 | 本期不做（明确排除） |
| --- | --- |
| 左侧栏一个入口图标 + 入口名称 | 快捷键、命令面板入口、设置页 |
| 一个主列页面，含品牌标题、输入框、搜索按钮 | 搜索建议、热搜榜、历史记录、多标签页 |
| 输入 → 点击/回车搜索 → 展示前 10 条结果 | 分页、翻页、结果排序/筛选 |
| 加载中、无结果、失败三种状态提示 | 结果缓存、离线回放、富媒体卡片 |
| 结果标题可点击并在新标签页打开原链接 | 站内预览、阅读模式、收藏 |
| 插件元数据（显示名「搜索引擎模拟器」、图标、中英描述） | 用户可配置项、多语言界面切换 |

## 3. 用户流程

1. 侧栏出现「搜索引擎模拟器」入口（图标为放大镜）。
2. 点击入口 → 主列切换到模拟搜索页，输入框自动获得焦点。
3. 输入关键词（空白或纯空格视为未输入），点击「搜索」或按回车。
4. 页面显示「搜索中…」，随后二选一：
   - 成功：显示「找到 N 条结果」+ 列表（最多 10 条）；
   - 失败：显示一行错误说明，输入框里的关键词保留，可直接重试。
5. 点击任一结果标题 → 新标签页打开该 URL。

## 4. 界面元素

| 元素 | 说明 |
| --- | --- |
| 品牌行 | 放大镜图标 + 文本「搜索引擎模拟器」，首次进入居中，搜索后置顶缩小 |
| 搜索框 | 单行文本输入，占位符「输入关键词，按回车或点击搜索」 |
| 搜索按钮 | 输入为空或搜索进行中时禁用 |
| 提示行 | 「搜索能力来自 DSH 本地搜索接口，最多展示 10 条结果。」 |
| 状态行 | 「搜索中…」／「没有找到与「X」相关的结果。」／错误说明 |
| 结果计数 | 「找到 N 条结果 · 关键词「X」」 |
| 结果行 | 标题（可点击、新标签页）、域名+路径、摘要（有则显示） |

视觉约束：容器、文字、边框、强调色全部使用 DSH 主题变量
（`--dsw-alias-*`），深浅色主题自动跟随；不引入任何外部 CSS/字体/图标库。

## 5. 数据契约

浏览器页面调用插件自己注册的同源 Host 路由：

```
GET /dsh-baidu/search?q=<URL 编码的关键词>
```

Host 侧调用 DSH 的 web 访问服务：`ctx.web.search({ query, maxResults: 10 })`。

成功响应 `200`：

```json
{
  "query": "原始关键词",
  "count": 10,
  "truncated": false,
  "sources": [
    { "url": "https://…", "title": "标题", "snippet": "摘要", "publishedAt": "" }
  ]
}
```

失败响应：`400 missing-query`（关键词为空）、`403 forbidden`（跨站调用）、
`405 method-not-allowed`（非 GET）、`502 search-failed`（搜索服务报错，带
`message`）、`503 search-unavailable`（本机没有可用的搜索服务）。

## 6. 行为规则

| 情况 | 期望表现 |
| --- | --- |
| 输入为空或纯空格 | 按钮禁用；不发起请求 |
| 搜索进行中再次点击/回车 | 忽略，不并发发起第二次请求 |
| 搜索成功但返回 0 条 | 显示「没有找到与「X」相关的结果。」 |
| 返回超过 10 条 | 只展示前 10 条，并提示「结果已被搜索服务截断」 |
| 本机未配置搜索服务 | 显示「本机没有可用的搜索服务，请先在 DSH 中配置网络搜索。」 |
| 搜索接口抛错 | 显示「搜索失败：<原因>」 |
| 点击结果标题 | 新标签页打开，`rel="noopener noreferrer"` |
| 关闭/切换面板后再次进入 | 回到初始状态（不保留上次结果） |

## 7. 技术实现要点

- **一个包、两半**：`index.js`（Host，注册路由）与 `client.js`（浏览器，注册 UI），
  由 `cordis.patch.yml` 一行 `dsh-baidu` 同时激活。
- **入口**：注册到 `sidebar.panellist`，`id` 为 `dsh-baidu`；壳层负责按钮与高亮，
  插件只提供图标和名称。
- **页面**：注册到 `main` 槽位，`key` 同为 `dsh-baidu`，与入口 id 一一对应。
- **不新增宿主能力**：只暴露一条只读、限流到 10 条的查询路由，不暴露任意 URL 抓取，
  也不做搜索结果的写入。
- **凭据按身份解析**：DeepSeek 官方搜索仅在「代表某个 Agent 调用」时使用账号登录态，
  而 HTTP 路由不在回合内。故 Host 半按「回合内 Agent → 依次尝试存活的根 Agent」借用身份，
  且只在「缺少凭据」时换下一个（此时请求尚未发出）。只配 API Key 的机器不借用身份。
- **无构建步骤**：两半都是普通 ESM / 浏览器工厂函数，装上即生效，便于社区阅读与改。

## 8. 验收标准

1. 安装后侧栏出现入口，图标与名称正确。
2. 点击入口，主列显示模拟搜索页。
3. 输入真实关键词搜索，能列出前 10 条真实结果，标题/链接/摘要正确。
4. 空输入、无结果、接口失败三种情况都有明确提示，不出现空白页或报错堆栈。
5. 深浅色主题下文字与控件都可读。

## 9. 歧义澄清记录

| 原始描述 | 可能的理解 | 本版采用 |
| --- | --- | --- |
| 「打开插件后」 | 设置页？侧栏面板？对话内嵌卡片？ | 侧栏入口 + 主列独立页面（最贴近「打开插件」的直觉） |
| 「模拟的搜索引擎界面」 | 仿百度首页？只要输入框？ | 仿搜索引擎首页布局（品牌 + 单输入框 + 按钮），搜索后转为结果列表 |
| 「界面可交互」 | 需要实时联想？ | 只要求输入、提交、点击结果跳转这三类交互 |
| 「DSH 本地的 searchAPI 接口」 | 浏览器直连？后端服务？ | Host 侧 `ctx.web.search`，与 `web_search` 工具同一能力 |
| 「列出前 10 个搜索结果」 | 固定 10 条？最多 10 条？ | 最多 10 条：请求 `maxResults: 10`，客户端再截一次 |
| 「模拟」 | 假数据？ | 真实调用搜索接口取真实结果，只在视觉上「模拟」搜索引擎 |
